La familia "JAX-" de Java/Jakarta EE

	JAXB (Java Architecture for XML Binding): Sirve para ligar/mapear XML a objetos Java.

		El proceso de pasar un objeto Java a un archivo XML se llama Marshalling.

		El proceso inverso (de XML a objeto Jav
a) se llama Unmarshalling.

	JAX-RS (Java API for RESTful Web Services): Sirve para crear servicios web tipo REST (usa anotaciones como @Path, @GET, @POST).

	JAX-WS (Java API for XML Web Services): Sirve para crear servicios web tipo SOAP (basados en XML).

	JAXR (Java API for XML Registries): Una tecnología antigua para interactuar con registros de servicios (como UDDI). 
	Está prácticamente obsoleta, pero sigue saliendo en los temarios.

JUnit Platform: Es la base sobre la que corren los tests en la JVM. 
Define la API para que las herramientas (como Eclipse, IntelliJ, Maven o Gradle)
puedan lanzar las pruebas.

JUnit Jupiter: Es el motor real y la interfaz de programación con la que escribes
 el código moderno. Contiene las anotaciones que verás abajo.

JUnit Vintage: Sirve para dar soporte hacia atrás y poder ejecutar tests antiguos
 escritos en JUnit 3 o JUnit 4.
 
@Test: Marca el método como una prueba unitaria. No debe devolver nada (voi
d) y
 normalmente no es público (en JUnit 5 basta con que sea de paquete).

@BeforeEach: El método se ejecuta antes de cada uno de los tests de la clase.
 Se usa para inicializar objetos o limpiar bases de datos en memoria para que cada test empiece de cero. (Equivale al @Before de JUnit 4).

@AfterEach: Se ejecuta después de cada uno de los tests.
 Se usa para liberar recursos. (Equivale al @After de JUnit 4).

@BeforeAll: Se ejecuta una sola vez, antes de que empiece cualquier test de la clase.
 Obligatoriamente tiene que ser un método estático (stati
c). Se usa para configuraciones
 pesadas (como arrancar un contenedor Docker de test o conectar a una BD pesad
a).

@AfterAll: Se ejecuta una sola vez, cuando han terminado todos los tests de la clase. También debe ser static.

@Disabled: Sirve para "saltarse" o ignorar una prueba temporalmente sin borrar el código. (Equivale al @Ignore de JUnit 4).


¡Cuidado con el orden de los parámetros! A diferencia de otros frameworks, 
en JUnit el orden estricto es: Assertions.assertEquals(esperado, actual).

Las más comunes que verás en los cuestionarios son:

    assertEquals(esperado, actual): Comprueba que los dos valores sean iguales.

    assertNotEquals(noEsperado, actual): Comprueba que difieran.

    assertTrue(condición) / assertFalse(condición): Evalúan expresiones booleanas.

    assertNull(objeto) / assertNotNull(objeto): Verifican la presencia de valores nulos
	(muy común al validar si un servicio de Jakarta inyectó bien un Bean CDI).

    assertTimeout(Duration.ofMillis(500), () -> { ... }): Falla si el código que está
	dentro de la expresión lambda tarda más tiempo del permitido (útil para probar rendimiento o bucles infinitos).
	
Creacionales (Creación de objetos):
 Ocultan cómo se crean los objetos. (Singleton, Factory Method, Abstract Factory, Builder, Prototype).

Estructurales (Composición de clases/objetos):
 Se enfocan en cómo se unen las clases y objetos para formar estructuras más grandes.
 (Adapter, Bridge, Composite, Decorator, Facade, Flyweight, Proxy).

De Comportamiento (Interacción y responsabilidades):
 Se encargan de los algoritmos y la asignación de responsabilidades entre objetos.
 (Observer, Strategy, Command, Chain of Responsibility, Iterator, State, Template Method, Mediator, Memento, Visitor).

Adapter (Adaptador): Convierte una interfaz incompatible en otra que el
 cliente espera para poder reutilizar código existente.

Bridge (Puente): Separa la abstracción de su implementación,
 permitiendo que ambas varíen y evolucionen de forma independiente.

Composite (Objeto compuesto): Organiza objetos en
 estructuras de árbol para representar jerarquías parte-todo, tratando igual a objetos individuales que a colecciones.

Decorator (Decorador): Añade funcionalidades a un objeto
 dinámicamente en tiempo de ejecución como alternativa flexible a la herencia.

Facade (Fachad
a): Proporciona una interfaz única y simplificada
 para acceder a un subsistema complejo y lleno de clases.

Flyweight (Peso ligero): Comparte objetos de forma eficiente
 para soportar grandes cantidades de elementos, reduciendo drásticamente el uso de memoria.

Proxy (Representante): Actúa como un intermediario o sustitut
o de otro objeto para controlar el acceso a él (por seguridad, coste o acceso remoto).
